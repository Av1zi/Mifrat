## Systemic patterns and proposed code fixes (not implemented)

1. **Derived `total_gb` overrides the kit total.** `total_gb` is recomputed as `module_count × module_size_gb` after the tier −1 override is applied, so a correct kit override (e.g. 2×24 GB → 48) ships as 96. Proposed fix: run the override after `infer_specs` / `fill_derived`, or exempt `total_gb` from inference when an override exists.
2. **`model` overrides are rewritten by canonical-name recompute.** `model` ships the derived string even when an override sets it (e.g. Jonsbo ZA-360B shows `3 -1 Jonsbo ZA- 12`). Proposed fix: apply override after `_recompute_canonical_names`, or make `model` a display-only override.
3. **Spec queue cap (30/category) hides cases.** Each rebuild surfaces a new batch; the owner sees a moving target. Proposed fix: paginate or report the true count.
4. **Hybrid-CPU clocks and iGPU names disagree between vendors.** P/E-core base clocks and short iGPU names ("Intel UHD") trigger `base_clock_ghz` / `integrated_graphics` conflicts that are both true. Proposed fix: a rule keyed to the CPU family, not a per-product dismissal.
5. **Packaging and "Box vs Tray" fuzzy matches.** Several Box/Tray pairs were initially merged through shared model text; they are now blocked. Proposed fix: make `packaging` a hard split key in the matcher, not a QA case.
6. **Accessory and external-SSD `form_factor` gap.** The `form_factor` schema enum (2.5"/M.2/…) does not fit portable SSDs and heat sinks, so 14 core gaps are structurally unfillable. Proposed fix: exclude external and accessory products from the `storage.form_factor` core requirement.
